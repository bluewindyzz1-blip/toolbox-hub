# 홈 카테고리 모바일 배치 오류 수정 검증

## 원인

기존 홈 화면은 선택된 카테고리의 하위 분류 패널을 세 개 카테고리 카드가 모두 끝난 뒤에 한 번만 렌더링했다. 따라서 모바일에서 파일 변환을 선택해도 패널이 단위 변환 카드 아래에 나타나, 선택 항목과 하위 분류의 연결이 잘못 보였다.

## 수정

데스크톱은 기존처럼 세 카테고리 행 바로 아래에 전체 폭 패널을 유지했다. 모바일 폭에서는 활성 카테고리의 카드 내부에 하위 분류 패널을 렌더링하고, 데스크톱 전용 패널은 숨기도록 분리했다. 패널 상태는 기존처럼 하나의 카테고리만 열리며, 다른 카테고리를 누르면 이전 카테고리는 닫힌다.

## 검증 중간 결과

로컬 데스크톱 폭에서 파일 변환 토글을 선택했을 때 파일 변환 분류 패널과 PDF 변환·PDF 편집·이미지 변환·문서 변환·파일 압축 링크가 카테고리 행 바로 아래에 표시되는 것을 확인했다. 다음 단계로 모바일 폭의 CSS 표시 규칙과 카테고리 전환 상태를 검증한다.

## 모바일 폭 모의 검증

브라우저에서 모바일 표시 규칙을 임시 적용한 뒤 파일 변환을 확인했다. 파일 변환 패널은 파일 변환 카드의 자식 DOM으로 생성됐고, 파일 변환 카드 상단보다 아래에 위치했다. 단위 변환 카드는 그보다 더 아래에 있어 기존처럼 모든 카드 뒤(단위 변환 아래)에 파일 변환 패널이 붙지 않는 구조임을 확인했다.

카테고리 전환의 첫 DOM 즉시 조회는 React 상태 갱신 이전 값을 반환했으므로, 다음 검증에서는 렌더링 반영 대기 후 파일 변환 패널 제거와 단위 변환 패널 배치 여부를 다시 확인한다.

## 전환 상태 점검

DOM의 카테고리 카드 라벨과 `aria-expanded`를 별도로 점검했다. 현재 로컬 화면에는 계산기 카드만 확장 상태이며, 그 카드 안에 모바일 패널이 하나 존재한다. 콘솔에서 텍스트 전체를 기준으로 카테고리를 찾는 방식은 활성 패널 텍스트와 섞여 정확한 전환 재현에 적합하지 않았다. 다음 단계에서는 각 카드의 고유 토글 버튼을 직접 눌러 파일 변환·단위 변환 전환을 확인한다.

## 파일 변환 직접 전환 검증

두 번째 토글 버튼(파일 변환)을 직접 실행한 뒤 React 상태가 반영될 때까지 대기해 확인했다. 계산기와 단위 변환은 `aria-expanded=false` 및 모바일 패널 없음이었고, 파일 변환만 `aria-expanded=true`와 모바일 패널을 가졌다. 파일 변환 카드 상단보다 모바일 패널 상단이 아래에 위치했다. 따라서 파일 변환 하위 목록은 파일 변환 카드 내부·바로 아래에만 렌더링된다.

## 단위 변환 전환 및 데스크톱 회귀

세 번째 토글 버튼(단위 변환)을 직접 실행한 뒤 파일 변환·계산기 패널이 모두 제거되고, 단위 변환 카드만 확장 상태가 되는 것을 확인했다. 단위 변환 카드 상단보다 해당 모바일 패널 상단이 아래에 위치했다.

모바일 폭 모의 스타일을 제거한 뒤에는 데스크톱 전용 패널만 `display:block`으로 표시되고, 모바일 카드 내부 패널은 `display:none`인 것을 확인했다. 데스크톱 패널은 기존처럼 카테고리 탐색기 내부에서 세 카드 행 다음에 전체 폭으로 표시된다.
